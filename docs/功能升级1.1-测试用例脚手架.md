# 功能升级 1.1 — 测试用例脚手架（bin/testcase.js）

> **版本**: v1.1 | **日期**: 2026-10-09 | **类型**: 新功能

## 一、升级背景

此前新建被测项目的测试用例目录靠手动复制（从 pdd-skills-v3 框架的 init 产物复制），存在两个问题：

1. 手动复制容易多套一层目录（存量 `testcases/<项目>/testcases/backend...` 双层结构即由此而来）
2. 样例文件（examples）无固定来源，依赖 pdd-skills-v3 框架项目

本次升级后，新项目用例目录一条命令自动生成，样例内置到本系统 skill 目录，**彻底解除对 pdd-skills-v3 框架的运行时依赖**。

## 二、变更清单

| # | 变更 | 位置 | 说明 |
|---|------|------|------|
| 1 | 迁移 testcase-modeler skill | `skill/testcase-modeler/`（14 文件，70K） | 建模师：自然语言 → YAML 用例；`examples/` 自带全套样例（login-flow、asset-eval-apply 的 yaml+env、yaml-format-guide.md） |
| 2 | 迁移 testcase-agent skill | `skill/testcase-agent/`（8 文件，116K） | 执行专家：YAML → Chrome DevTools MCP E2E 执行 + HTML 报告（含 5 条铁律、自愈策略、报告模板） |
| 3 | 新增脚手架 CLI | `bin/testcase.js` + `bin/testcase.cmd` | 零依赖 CommonJS，node 16/22 通用，无需 package.json；`.cmd` 为 Windows 启动器（对齐 run-test.cmd 模式） |

### 补充踩坑（2026-10-09 实测发现）

- **`.js` 不能双击直接运行**：Windows 将 `.js` 关联到 Windows Script Host（JScript 解释器），双击 `testcase.js` 报 `800A03F6 无效字符`（首行 shebang `#!` 对 JScript 非法）。正确用法：命令行执行 `bin\testcase ...`（cmd 启动器）或 `node bin\testcase.js ...`
- **批处理注释不能写中文**：`testcase.cmd` 初版含中文 rem 注释，UTF-8 字节在 GBK 代码页下被错误拆解成命令执行（`'r' 不是内部或外部命令`），已改全 ASCII 注释

## 三、使用方式

### init — 生成测试用例骨架

```bash
node bin\testcase.js init <项目名>       # 常规：合并模式
node bin\testcase.js init <项目名> -f   # 强制：覆盖已存在的模板文件
```

生成结构（对齐 PDD 框架 ruoyi 模板的 testcases 部分）：

```
testcases/<项目名>/
├── README.md                     # 项目用例说明（含执行方式）
├── backend/                      # 后端 API 用例
├── frontend/                     # 前端 E2E 用例（yaml + env 成对）
├── shared/                       # 共享测试数据
├── reports/                      # 测试报告
├── scripts/
│   ├── run-all-tests.ps1
│   ├── run-backend-tests.ps1
│   └── run-frontend-tests.ps1    # 自动扫描执行 frontend/ 下全部 yaml
└── examples/                     # 5 个样例，自动从 skill/testcase-modeler/examples 复制
    ├── login-flow.yaml / .env
    ├── asset-eval-apply.yaml / .env
    └── yaml-format-guide.md
```

生成后执行：

```bash
cd tests
python testcase-ai.py ../testcases/<项目名>/frontend/<case>.yaml
```

### list — 项目清单

```bash
node bin\testcase.js list
```

输出各项目的 yaml 用例数与 test-result 报告轮次，兼容存量双层结构（`<项目>/testcases/...`）的统计。

### 安全机制

- **默认合并模式**：已存在的文件/目录一律 `[SKIP]` 跳过，不会覆盖已写好的用例；只有显式 `-f`/`--force` 才覆盖
- **项目名校验**：拒绝包含 `\ / : * ? " < > |` 或以 `.` 开头的名称
- `test-result/` 运行产物任何时候都不受 init 影响
